# Taskboard API: Projects, tasks and comments for Taskboard workspaces. — MCP server

Generated by [`promptise mcpcast`](https://docs.promptise.com/mcp/server/mcpcast/) from
`openapi.json`. Any MCP-capable AI — Claude Desktop, Claude Code,
Cursor, or a Promptise agent — can now use this API safely.

- **Upstream API:** `http://127.0.0.1:8000`
- **Safety profile:** `full`
- **Tools:** 14 (7 require human approval)
- **Not exposed:** 0 operations (listed below, each with a reason)

## Run

```bash
pip install promptise
python server.py                        # stdio — for desktop clients
python server.py --transport http       # http://127.0.0.1:8080/mcp
```

The server is a package. Install it and it is a command, a module and an image:

```bash
pip install -e ".[dev]"
taskboard-mcp                                  # same as python server.py
python -m taskboard_mcp --transport http
pytest                                  # the generated tests in tests/
docker build -t taskboard-mcp . && docker run --env-file .env -p 8080:8080 taskboard-mcp
```

## Connect an AI

> **This server needs an `x-api-key` header on every request, which a stdio client cannot send.** Run it over HTTP (`python server.py --transport http`) and point your client at `http://127.0.0.1:8080/mcp` with the header, or regenerate with `--auth env-token` for a personal stdio server.

Run the server over HTTP and give every client the `x-api-key` header (one of the keys in `MCPCAST_CLIENT_KEYS`):

```bash
python server.py --transport http        # http://127.0.0.1:8080/mcp
```

**Claude Code:**

```bash
claude mcp add taskboard --transport http http://127.0.0.1:8080/mcp --header "x-api-key: <key>"
```

**Cursor** — add to `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "taskboard": { "url": "http://127.0.0.1:8080/mcp", "headers": { "x-api-key": "<key>" } }
  }
}
```

**Claude Desktop** — `claude_desktop_config.json` has no header field for HTTP servers, so Claude Desktop cannot present the `x-api-key` header this server requires; for a personal Desktop server regenerate with `--auth env-token`.

**Promptise agent** — `HTTPServerSpec` sends the header on every request:

```python
from promptise import build_agent, HTTPServerSpec

agent = await build_agent(
    model="openai:gpt-5-mini",
    servers={"taskboard": HTTPServerSpec(url="http://127.0.0.1:8080/mcp", api_key="<key>")},
)
```

## Authentication

**Auth mode: `api-key`.** MCP clients present an API key in the `x-api-key` header. Each key names a tenant, and each tenant has its own upstream credential, sent as the `Authorization` header — clients never see the upstream secret. `MCPCAST_CLIENT_KEYS` is read once at start-up (rotating keys needs a restart); `MCPCAST_UPSTREAM_TOKENS` is read on every call, so upstream credentials rotate without a restart. Mint each client key — the server refuses to start with no key, with a `<placeholder>` key or with a key copied from documentation (`sk-acme`, `sk-reviewer`), which anyone can read:

```bash
python -c 'import secrets; print("sk-" + secrets.token_urlsafe(32))'
export MCPCAST_CLIENT_KEYS='{"sk-<generated>": {"client_id": "acme-agent", "tenant_id": "acme", "roles": []}}'
export MCPCAST_UPSTREAM_TOKENS='{"acme": "Bearer <your API token>"}'
```

## Human approval

These tools change or delete data and are **approval-gated server-side** — any MCP client, not just Promptise agents, is held until a human decides, and a timeout denies by default: `create_project`, `update_project`, `delete_project`, `create_task`, `update_task`, `delete_task`, `add_comment`.

**Approval mode: `pending`** (independent four-eyes review, scoped to the tenant). A gated call waits in a pending store; a reviewer of the **same tenant** holding the `approver` role lists and decides it with the `approvals_list` / `approvals_decide` tools. A caller can never approve their own request, and reviewers never see other tenants' calls. Capacity is bounded too: at most `MCPCAST_MAX_PENDING` calls wait server-wide, `MCPCAST_MAX_PENDING_PER_TENANT` per tenant and `MCPCAST_MAX_PENDING_PER_CLIENT` per API key — beyond a cap the call is denied at once, so one tenant cannot fill the store for the others.

Reviewers are MCP clients whose key in `MCPCAST_CLIENT_KEYS` carries the `approver` role and the tenant they review for (mint every key with `python -c 'import secrets; print("sk-" + secrets.token_urlsafe(32))'`; the server refuses placeholder and documentation keys):

```bash
export MCPCAST_CLIENT_KEYS='{"sk-<agent key>": {"client_id": "acme-agent", "tenant_id": "acme", "roles": []}, "sk-<reviewer key>": {"client_id": "dana", "tenant_id": "acme", "roles": ["approver"]}}'
```

## Configuration

Copy `.env.example` to `.env` next to `server.py` and fill it in: `python server.py`,
`python -m taskboard_mcp` and `taskboard-mcp` read it at start-up (a variable already set in the
environment wins; `PROMPTISE_NO_DOTENV=1` skips the file). `promptise serve` reads the
working directory's `.env` itself; the generated tests and `--eval` never read it.

| Variable | Purpose | Default |
|---|---|---|
| `MCPCAST_BASE_URL` | Override the upstream base URL for every tool — including operations that declare their own server. One clean URL: no `user:password@`, query string or fragment (refused at start-up) | `http://127.0.0.1:8000` |
| `MCPCAST_UPSTREAM_TOKEN` | `env-token` mode: the value sent upstream as the `Authorization` header (read per call) | — |
| `MCPCAST_CLIENT_KEYS` | `api-key` mode: MCP client keys, read once at start-up; placeholder (`<…>`) and documentation keys are refused | — |
| `MCPCAST_UPSTREAM_TOKENS` | `api-key` mode: each tenant's upstream credential, sent as the `Authorization` header, read per call | — |
| `MCPCAST_TIMEOUT` | Total time one upstream call may take, in seconds — connecting, sending, waiting for the response and reading its body together; past it the tool fails with `UPSTREAM_TIMEOUT` (retryable) | `30` |
| `MCPCAST_APPROVAL_TIMEOUT` | How long a gated call waits for a decision before it is denied | `300` |
| `MCPCAST_MAX_PENDING` | `pending` approval: how many gated calls may wait for a reviewer at once, server-wide; beyond it a call is denied immediately | `100` |
| `MCPCAST_MAX_PENDING_PER_TENANT` | `pending` approval: how many of those one tenant may hold, whatever the number of its API keys | `40` |
| `MCPCAST_MAX_PENDING_PER_CLIENT` | `pending` approval: how many one client (API key) may hold | `20` |
| `MCPCAST_MAX_RESPONSE_BYTES` | Largest upstream response body passed on to the agent; beyond it the call fails with `UPSTREAM_RESPONSE_TOO_LARGE` | `1048576` |
| `MCPCAST_ERROR_EXCERPT_CHARS` | An upstream HTTP error is returned as `UPSTREAM_ERROR` with this many characters of the response body; the credential is scrubbed to `[redacted]` before the excerpt is cut — it is your own API's error page, but check what else it contains before exposing the server to third parties (`0` hides it) | `500` |
| `MCPCAST_ALLOW_INSECURE_HTTP` | Set to `1` to send the upstream credential to a plain-`http://` host that is not loopback (otherwise `UPSTREAM_INSECURE`) | unset |
| `MCPCAST_PUBLIC` | `none` / `env-token` modes: set to `1` to bind a non-loopback address (the `--public` flag) | unset |
